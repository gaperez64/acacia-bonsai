## 2. What the input actually provides

The suite's `all.list` has 1,524 IDs; `tlsf-sources.tsv` maps all of them to existing files in `tlsf-corpus/` (`tests/suites/benchmarks/syntcomp26/README.md:1-25`). A read-only scan of those 1,524 TLSF files, stripping block/line comments before inspecting `PARAMETERS`, found:

| Declared parameters | Inputs | Names |
|---|---:|---|
| None | 790 | — |
| One | 454 | `n` |
| Two | 256 | `n,u` |
| Two | 15 | `N,M` |
| Two | 9 | `xN,yN` |
| **Any declaration** | **734** | `n` occurs in 710 inputs; `u` 256; `N` and `M` 15 each; `xN` and `yN` 9 each |

This is source-text census, not a proof that every parameter value or lowering is valid. The existing production eligibility census admitted 72, declined 1,070 at the one-call parameter-signature gate (the 790 nonparametric inputs plus 280 two-parameter inputs), and divided the other 454 `n`-only inputs into 72 eligible, 317 content-mismatch, 39 route-disabled and 26 seed-guarded (`benchmarking/gr1-par2-20260923/campaign/eligibility-v3-summary.md:1-28`; `benchmarking/param-lift-20260922/legacy_lift/capabilities.py:513-548,637-660`). Thus the present 72 is a registry coverage count, not a fundamental GR(1) or parametric eligibility count.

Four serial, read-only `tlsfinfo --parameters` and `tlsf2tlsf --basic --param ...` probes (each subprocess bounded to four seconds) confirmed that the *same input bytes* can be re-instantiated: `arbiter_pb_5_pe_.tlsf` at `n=3` changes expanded I/O 5/5 to 3/3; `full_arbiter_unreal1_pb_2_10_pe_.tlsf` at `n=3,u=4` changes 2/2 to 3/3 and changes the normalized formula; `chomp_pb_2_2_pe_.tlsf` at `N=3,M=2` changes 4/10 to 5/13; `robot_grid_pb_2_2_pe_.tlsf` at `xN=3,yN=2` changes 4/5 to 6/5 and changes expanded generated logic. The latter two source files use parameterized buses, index ranges and derived grid expressions (`tlsf-corpus/chomp_pb_2_2_pe_.tlsf:9-26,38-46`; `tlsf-corpus/robot_grid_pb_2_2_pe_.tlsf:17-21,76-87`). These probes establish tool capability on representative shapes, not corpus-wide override success.

**Necessary assumption:** the actual supplied input remains parametric TLSF, its parameter declarations and generator structure survive submission, and each selected override can be re-lowered to an exact smaller instance. If an organiser expands parameters away (790 existing inputs do), there is no authorized way to recover a sibling source from a filename, adjacent corpus file, or guessed template. Lifting must decline. A direct, exact GR(1) solve with a checked certificate remains possible for any independently reducible target, whether parametric or not.

## 3. Replacement route

1. **Admission and target identity.** Hash/spool the actual input once; ask SyFCo for parameters and concrete values; lower the target in exact mode with the same bytes and explicit values. `gr1_monitor_game.py` already provides exact per-conjunct DBA reduction for B/G/S/O/R formulas and rejects unsupported Mealy/target combinations (`tlsf-tools/scripts/gr1_monitor_game.py:1-25,697-725`). If it rejects, decline. No family/name/content match is needed. Preserve lowered formula and ownership hashes so the checker game and reported answer are bound to this request. New: source/override identity independent of capability.
2. **Seed choice and degeneracy.** For one index-bearing parameter, try increasing legal values below the target, beginning at 1, never using the target. Instantiate each from the same source; skip parser/constraint failures. Require a window of two consecutive valid sizes with matching alpha-normalized local-conjunct origins, bus-schema categories, role signatures, goal classes and state ABI; use those two as seeds and, if budget permits, the next valid size as a confirmation seed. A disappearing pairwise conjunct at size 2 is then a detected regime change rather than an offline `stable_from` lookup. A later change invalidates the window; continue until the global attempt/time limit, then decline. Existing `m4-analysis/census_align.py:81-170` shows the shape test; `Instance.load` and `_provenance_role_class_count` supply part of it (`generalizer.py:786-793,1016-1158`). New: online window search, genuine source-origin IDs and counterexamples to apparent stability. Two matching samples are only a heuristic, never an all-size proof.
3. **Structural coordinates and roles.** Extend the TLSF frontend/lowering interface to emit stable source declaration, parameter-axis, generator and conjunct-origin IDs plus concrete index tuples. Normalize AST variables and exact monitor transitions across sizes; use formula/ownership fingerprints, not signal spellings. Build role classes from each index's multiset of incident origin/relative-index records. Match special positions by their *structural incidence*, not `index == 0`. For encoded buses (`nbits(n)`), a signal bit is a representation bit with a width function, not an extra client; for two-dimensional arrays retain coordinate tuples. Existing role inventory/projection machinery is reusable only after this provenance fix (`generalizer.py:1050-1158,2323-2471`); current `source_origin_metadata.available=false` makes that fix prerequisite (`tlsf-tools/scripts/gr1_monitor_game.py:639-650`).
4. **Arity and schemas.** For each learned predicate (invariant, every rank, moves), try `k=0,1,...,K` in order, with at least one seed strictly larger than `k`. Require exact reconstruction from every qualifying seed and equality of normalized templates across seeds, then instantiate at the target. Current `_predicate_templates` already escalates per predicate and does exact BDD reconstruction (`generalizer.py:2611-2672`); remove its family base arity and its `k <= n` degeneracy exception. Derive cardinality bus schemas via symbolic equivalence/count signatures already started by `_symmetric_signature` (`tlsf-tools/scripts/gr1_monitor_game.py:540-596`); derive temporal/bus state abstraction by checked AST/automaton semantics. If an unbounded-width monitor or unmatched bus state needs a family-specific trick, decline. Retain the global `K=4` as an explicit, revisable cost cap, **not** a claim that all unseen families have arity at most four.
5. **Proof method and proposal.** Use a global order: attempt ordinary policy export/check, then region-only check of the same system certificate if policy generation/checking fails for capacity or deadline reasons and time remains. Alternatively preselect region by a single frozen global cost rule; neither choice may inspect names or historical family outcomes. The existing generic checker offers both (`generalizer.py:3803-3918`; `tlsf-tools/src/main_tlsfcertcheck.c:195-215,687-710`). The special cardinality-action optimization may be added only with a semantic precondition verified from the target game; basic composition already exists. Wrong seeds, arity, role or method produce a failed check/UNKNOWN, not a verdict.
6. **UNREAL and multiple parameters.** Direct exact target solve is a parallel generic option within the same lift slice, especially when no stable seed window is found; it is explicitly reported as `direct-certified`, not lifting. Reuse `run_exact_direct` and exact environment counterstrategy checking (`benchmarking/param-lift-20260922/legacy_lift/generalizer.py:4499-4739`; `tlsf-tools/src/main_tlsfcertcheck.c:627-681`). Pass an explicit GR(1) game profile when the exact reducer produced one: the solver's *auto* profile currently also requires a controllable input (`tlsf-tools/src/main_tlsfsolve.c:188-224`), which is an accidental obstacle to the stated any-reducible-input scope. For multiple parameters, inspect source provenance to find index-bearing axes; vary one axis at a time while holding all others at actual target values, and require consistent cross-axis schema when combining. If axes interact, make only a bounded rectangular probe under the same budget; otherwise decline lifting and optionally try direct exact solve. Never assume a parameter called `n` or that every parameter measures clients. The four probes above show why this matters.
7. **Declines and accounting.** Decline on absent/nonconcrete parameters for lifting, invalid overrides, unsupported exact reduction/semantics, missing structural provenance, incompatible seed/target ABI or role classes, no stable window, arity above cap, unproved bus abstraction, inconsistent ranks, checker error/refutation, resource cap or expired deadline. Reserve fallback time before any expensive discovery. Reuse `AbsoluteDeadline`, progress evidence, wrapper process-group cancellation and fallback (`generalizer.py:548-573,699-730`; `scripts/acacia-lift-portfolio.py:503-589`). Charge *all* parsing, seed solves, schema search, exact attempts and checks before B; never use warm family caches in primary results.

Suggested **global** starting knobs to freeze before evaluation: at most six attempted sizes per axis, two agreeing seeds plus at most one confirmation seed, `K=4`, and at most 20% of the wrapper's lift slice for source/seed/schema discovery. These are cost controls, not per-family constants; use the remaining slice for candidate/check or exact direct solve. The wrapper currently gives lifting one third of the outer cap by default and caps source binding at `min(1 s, 5% of cap)` (`scripts/acacia-lift-portfolio.py:69-105,503-519`). At a 17 s cap its whole lift slice is about 5.7 s, so even a small failed online search can remove meaningful time from B. If the proposed discovery share is too restrictive, change it on a disclosed development split and freeze it before holdout; do not silently tune by family.

## 4. Soundness boundary

The source parameter override defines a different *seed* problem, never a theorem about the target. Every target candidate is untrusted. The exact target monitor game is built from the bound actual source/values; a certificate (and policy when needed) is checked by `tlsfcertcheck` against that target game. The checker verifies transition, safety, rank/fairness and strategy obligations independently of the guessed schema (`tlsf-tools/src/main_tlsfcertcheck.c:4-24,4270-4330`). Only a verified target check can produce REALIZABLE. Direct UNREALIZABLE needs exact reduction, environment-side exported certificate/counterstrategy and successful independent check; strict semantics may only justify REALIZABLE (`tlsf-tools/scripts/gr1_monitor_game.py:14-25`; `benchmarking/param-lift-20260922/legacy_lift/runner.py:512-550`). Source/game/certificate hashes and side/semantics must agree through the wrapper. A failed, timed-out or unsupported check is UNKNOWN and falls back. This establishes **requested-target** soundness, not an all-parameter theorem; `prove_all_n.py:1-16,256-273` explains why the current concrete BDD objects cannot support the latter.

## 6. Reviewable implementation stages and evaluation

1. **Source-only binding.** Add generic parameter/override identity, exact target construction and evidence without changing certificate algorithms. Remove runtime manifest/template admission and historical reproducer lookup from the wrapper path. Test same bytes under arbitrary file basenames, mutation of source after binding, absent parameters and multi-parameter parsing.
2. **True provenance.** Teach tlsf-tools/frontend to retain declaration, generator, conjunct and dimension origin through expansion; version the provenance format. Differentially check emitted I/O and formulas against the existing lowering, including buses, ranges, enum/encoded widths, repeated indices and alpha-renamed signals. Decline when an origin cannot be made unambiguous.
3. **Online schema discovery.** Implement bounded seed window, role/ABI comparison, per-predicate arity search, and semantics-based bus schemas. Keep the old M4 TSVs only as retrospective comparisons. Unit examples should include a degenerate smallest size, a newly introduced role, a pairwise conjunct hidden at size two, and a truly `k=n` predicate.
4. **Generic proof paths.** Remove collector and three-name structured branch from production dispatch; use generic moves, policy/region order and exact dual target solve. Require independent target checker acceptance, mutation tests of certificate/game/side/override, deadline and fallback tests. Keep historical implementation available only as an isolated baseline until comparison is complete.
5. **Portfolio measurement.** Freeze the few global knobs and source/provenance schema, then run cold full-pipeline comparisons with identical outer deadlines, fallback B and memory limits. Report source eligibility, seed/arity attempts, direct versus lifted verdicts, checker failures, B wins/losses and all time charged before B. Evaluate separately on truly unseen source groups and a run with randomized benchmark basenames and alpha-renamed signal identifiers; the latter must leave outcomes invariant after semantic renaming. The already inspected SYNTCOMP26 families are development data, not an untouched test set. Split by source-template group rather than sibling parameter instance, disclose the split and knobs, and use fresh families or later corpus for the final holdout. No row-level or family-level retuning on the holdout.

Acceptance criterion: no runtime source/capability table, family literal, family-based switch, filename/basename lookup or signal-name pattern can alter admission, seeds, schema, proof method or verdict. A linter/search review plus renamed and unseen-source differential run should enforce this; the independent target checker remains the final decision authority.
