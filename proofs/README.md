# Symmetry reduction proofs

This standalone development uses Lean 4.35.0 and core only. The default target
checks every module and both example files, treating warnings as errors. The
proofs use no admitted steps, custom axioms, native decision procedures or partial
functions. Historical line references in the Lean comments are relative to
`src/` at master `bbf12523` (including PR #336). The correspondence table below
uses checked source anchors in the current tree, also relative to `src/`.

What is proved:

- Accepted detector candidates preserve state/AP bijections, init, acceptance,
  I/O, coordinate caps and enabled edges in both directions.
- Successor, safety, backward preimages, Pre/CPre, stages and winners respect
  symmetry in both protagonist frames. Finite iteration gives the greatest safe fixed point.
- Successful raw builders construct valid `SweepPlan`s, including inverse
  layouts, generated transports, complete input coverage and orbit closure.
- Snapshot sweeps and representative/closure solvers have the plain final region
  and verdict, including early initial-out exits and reachable picker completion.
- Physical input cubes and whole-row action deduplication refine full response
  classes; caching and priority changes preserve this relation.
- MONA's low-first input and high-first output walks keep empty responses in
  both symbolic modes and the explicit path; their tables satisfy `Refines`.
- Boolean preprocessing supplies the stored-forward picker condition. Adaptive
  bound raises preserve soundness, and a successful solve certifies its returned actual K.

## Trusted gap

The Lean kernel checks these mathematical ports; they do not extract or verify
the compiled C++ binary. The correspondence assumptions cover BDDs, containers
and machine arithmetic. For BDDs, they cover construction, canonical identity,
support/dictionary interpretation, ordered paths and endpoint decoding.
`mona_refinement` assumes the diagram denotes the endpoint relation and its output
paths satisfy `Diagram.Realizable`. The explicit truth-table constructor proves
both properties internally. Its visitors skip unencoded false nodes, and every
endpoint row, including the empty relation, receives an injective terminal ID.
AP dictionary rows must have distinct identifiers.

Antichain insertion, pruning, meet, bulk construction, SIMD/Boolean containers,
C++ maps and caches must implement their mathematical interfaces. Machine counter,
rank, shift and priority arithmetic must agree with the mathematical operations.
The proof's pinned revision used unchecked `k += kinc` in the shared loops.
Current C++ calls `checked_next_k` at both equivariant shared-loop increments;
this checks representability while retaining the full-step schedule, distinct
from the ordinary clamped schedule. K and lifted ranks must still stay in range.
Compiled execution, interruption, cancellation, formula/LTL translation,
detector-search completeness and Boolean optimization as an LTL transformation
are outside scope.

Backward/picker completion requires K ≥ 1 and safe maxima. Stored Boolean forward
steps also require `BooleanClosed`, which the ported preprocessing proves.
The rejecting Boolean self-loop mutant violates this condition; production's bare
SIMD vector stores scalar values. Adaptive raises require a positive actual delta,
a uniform counting lift and a Boolean reset. Shared scheduling can overshoot kmax.
Refutation at an overshoot implies refutation at kmax; success certifies actual K.
The schedule mutant wins at 3 and loses at the configured maximum 2.

## Build

From the repository root, run the same script used by CI:

```sh
proofs/check.sh
```

The script defaults to exactly one Lean process on the shared 7.6 GiB machine,
with `LEAN_NUM_THREADS=1`, `LEAN_STACK_SIZE_KB=2048` and `LEAN_MAIN_USE_THREAD=0`.
Do not set `ulimit -v`. These environment variables may be overridden; direct
source checks pass the worker and stack values to Lean explicitly. The library
keeps its one-worker, synchronous elaboration settings from `lakefile.toml`.
Module checks remain sequential everywhere so imports are refreshed before
their users. CI keeps these defaults; cold-cache full runs measured 1–1.5 minutes.

The script rejects `sorry`, `admit`, custom `axiom`, `native_decide` and `partial`
tokens, then elaborates and caches each module before the final build, with
warnings as errors and timing for each step. Source elaboration always runs,
including after an exact Lake cache hit. Before auditing, the script explicitly
builds every discovered module target with `--rehash`, including unimported nested
sources, so a stale cache cannot hide a source error. This project has no
`lean_exe` targets or external Lean/golden/data inputs; tlsf-tools' executables are a separate Lake
project and are not part of this build.

After the full build, `AuditAxioms.lean` imports each library module in a separate
Lean process, allowing executable roots to define their own global `main`, and uses
`Lean.collectAxioms` on every declaration defined there, including private and
generated constants. Only `propext`, `Classical.choice` and `Quot.sound` are
allowed; `sorryAx` and generated native-decision axioms fail the check.
CI also runs `python3 proofs/test-axiom-audit.py`: tiny compiled fixtures verify
the allowlist and reject `native_decide`, `sorry` and custom axioms without
building the library. Fixtures explicitly select `proofs/lean-toolchain`, and
also cover duplicate `main` definitions, missing imports and stale unimported
sources. On the shared machine, run these fixtures only with:

```sh
TMPDIR=/home/gaperez/scratch/leanci/tmp LEAN_NUM_THREADS=1 \
  systemd-run --user --scope -p MemoryMax=2G -p MemorySwapMax=0 \
  python3 proofs/test-axiom-audit.py
```

Mark **Lean required** as the required branch-protection check. It always runs
after both `changes` and `lean`, and fails on detector/correspondence failures
or any unsuccessful required Lean run. It accepts a skipped Lean run only when
the successful detector explicitly returned `false`. The workflow runs both
correspondence checkers on every PR, regardless of target branch. The detector
uses NUL-delimited Git paths and checks both sides of renames.

Run `python3 -m pytest tests/pytest/test_lean_ci.py -q` for the lightweight path,
gate, command-failure and correspondence regressions; CI runs them in `changes`.

## Issue #454 obligations

`Quotient.lean` proves orbit quotients of turn-based games sound for any
objective on the priority sequence, parity included. `CountGame.lean` and
`CountTemporal.lean` provide the generic reduction and temporal lemmas.
`CountEngine.lean` implements the concrete predicates, since/breakpoint bits,
events and resets at `symmetric_count.cc` revision `6c6da84a`, and connects them
to the spec's game. Namespaces are `Symmetry.CountGame`, `Symmetry.CountTemporal`
and `Symmetry.CountEngine`. Counts and transition tables are mathematical;
the compiled-code, BDD and machine-arithmetic boundary still applies.
`Translates` assumes only correctness of the global parity translator for the
**encoded** formula. `Clause.correct` proves the original-to-encoded equivalence,
including local Inf/Fin/sink acceptance and position-0 since conjuncts.
`Certified` requires strategy entries only on reachable count keys; the adapter
completes unvisited entries and chooses raw indexed edge witnesses before
canonicalization. `engine_spec_verdict` transfers either certified winner from
the zero-bit initial key and excludes an opposite winner for the original spec.
